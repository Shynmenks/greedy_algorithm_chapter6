Greedy Algorithms · 1 of 8

Introduction to Greedy Algorithms

A greedy algorithm builds a solution piece by piece, always taking the choice that looks best right now, and never goes back to change it.

How it works

  1. Start from the initial state.
  2. Look at the options available.
  3. Take the best-looking one.
  4. Repeat until done.

Classic greedy algorithms

Fractional Knapsack, Dijkstra, Kruskal, Prim, Huffman coding, Activity Selection.

Coins 1, 2, 5, 10: make 39

10 + 10 + 10, then 5, then 2 + 2. 6 coins, optimal.

But not always optimal

Make 20 with coins 18, 10, 1. Greedy takes 18 + 1 + 1 = 3 coins. Better: 10 + 10 = 2 coins.

Greedy Algorithms · 1 of 8

Characteristics of Greedy Algorithms

Simple

Easy to implement and easy to reason about.

Efficient

Often quick. Preferred over dynamic programming where both apply: Jump Game, and Dijkstra over Bellman-Ford when no weights are negative.

No looking back

Decisions use current information only. Previous choices are never reconsidered and the algorithm does not look ahead.

Approximation for hard problems

Traveling Salesman (NP-hard): always go to the nearest unvisited city. Not always optimal, but approximately optimal.

Greedy Algorithms · 2 of 8

Greedy-Choice Property and Optimal Substructure

A problem needs both for a greedy algorithm to be correct.

Greedy-choice property

Some optimal solution always contains the greedy choice, so earlier decisions never need reconsidering.

Proof: exchange argument. Take any optimal solution, swap in the greedy choice, show it is no worse.

Optimal substructure

An optimal solution contains optimal solutions to its subproblems. After the greedy choice, one smaller problem of the same form remains.

Proof: cut-and-paste. A better subsolution would improve the whole, a contradiction.

Greedy vs. dynamic programming

DP tries all choices and picks the best after solving subproblems. Greedy commits to one choice before solving subproblems. Optimal substructure is shared; the greedy-choice property is what greedy adds.

Activity Selection / Unweighted Interval Scheduling

One room, many requests, each with a start and finish time. Only one activity at a time. Choose the largest set that does not overlap.

TermMeaning
Inputn activities, each with a start time and a finish time
CompatibleOne finishes before (or exactly when) the other starts
GoalLargest set where every pair is compatible
UnweightedEvery activity counts as 1; only the count matters

Applications

Classroom or meeting-room scheduling · CPU and task scheduling · single-machine job scheduling · booking events at a single venue.

Greedy Algorithms · 4 of 8

Earliest-Finish-Time Strategy

Always pick the activity that finishes first. Finishing early leaves the most room for what comes next.

The rule

  1. Sort activities by finish time.
  2. Pick the first one.
  3. Pick the next whose start ≥ last finish.
  4. Repeat until none are left.

Pseudocode

sort activities by finish time
selected = [first activity]
last = finish of first
for each remaining activity a:
    if start(a) >= last:
        add a to selected
        last = finish(a)
return selected

Why it makes sense

The earlier an activity ends, the more time remains. We never waste room on a long activity when one that ends sooner is available. The sort is the expensive line; the loop is one pass.

Greedy Algorithms · 5 of 8

Python Implementation

def activity_selection(activities):
    # activities: list of (name, start, finish)
    activities.sort(key=lambda a: a[2])      # sort by finish time
    selected = [activities[0]]
    last_finish = activities[0][2]
    for name, start, finish in activities[1:]:
        if start >= last_finish:              # compatible
            selected.append((name, start, finish))
            last_finish = finish
    return selected

acts = [("A",1,3),("B",2,5),("C",4,7),("D",1,8),("E",5,9),("F",8,10)]
result = activity_selection(acts)
print("Selected:", [a[0] for a in result])   # ['A', 'C', 'F']
print("Count:", len(result))                  # 3

Activity Selection Time Complexity

StepTime
Sort by finish timeO(n log n)
Selection pass (scan)O(n)
TotalO(n log n + n) = O(n log n)

The scan is O(n)

  • The loop visits each activity exactly once.
  • Each visit: one comparison, at most two assignments.
  • n visits × constant work = O(n)

Sorting dominates

  • The larger term wins when costs are added.
  • Line 1 (the sort) is the expensive part; lines 4 to 7 check each activity once.
  • Sorted input: only the scan remains, O(n).

Greedy Algorithms · 7 of 8

Why Earliest Finish Works

Let g be the greedy first pick and O any optimal schedule.

Exchange argument

  1. Let x be the first activity in O.
  2. g finishes no later than x, so swapping creates no overlap.
  3. Same size, still optimal: some optimal solution starts with g.
  4. Repeat on the compatible rest; by induction greedy is optimal.

Greedy stays ahead

  • Base: greedy’s first pick has the earliest finish of all.
  • Step: the k-th greedy pick never finishes later than the k-th pick of any optimal solution.
  • Conclusion: if optimal had more activities, greedy would still have a compatible one left and would not have stopped.

Both properties at work

Greedy-choice: an optimal solution includes the earliest finisher. Optimal substructure: what remains is the same problem, smaller.

Greedy Algorithms · 8 of 8

When Greedy Algorithms Fail

A rule that sounds smart still needs a proof.

Coin change {1, 3, 4}, make 6

Greedy (largest first): 4 + 1 + 1 = 3 coins. Optimal: 3 + 3 = 2 coins. The locally best coin locks you out of a better answer.

0/1 knapsack, capacity 50

Items (weight, value): (10,60), (20,100), (30,120). Greedy by value/weight: items 1, 2 = 160. Optimal: items 2, 3 = 220.

Shortest path, negative edges

Dijkstra works for non-negative weights. With negative edges a finalized node can later be improved. Use Bellman-Ford.

Where greedy does work

Standard coins {1, 5, 10, 25}; fractional knapsack (fractions allowed); Dijkstra with non-negative weights; Huffman, Kruskal, Prim.

How to Tell, and What to Remember

How to tell if greedy will work

  • Try an exchange argument or “greedy stays ahead”.
  • Look for counterexamples on small inputs.
  • Check both properties.
  • If you cannot prove it, consider dynamic programming.
